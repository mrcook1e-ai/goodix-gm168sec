В этом каталоге собрана документация по экспериментальному оверлею драйвера
[libfprint](https://gitlab.freedesktop.org/libfprint/libfprint) для **Goodix GM168SEC**
(`27c6:589a`), его интеграции сопоставления `FPI_PRINT_SIGFM`, подсистеме восстановления
существующего PSK только в памяти без записи и инженерным границам проекта,
основанным на принципе «чистой комнаты».

Подробные технические руководства ниже пока доступны на английском языке;
русские версии входных страниц и руководства по айдентике уже включены.

> **Область применения и статус**
>
> - **Экспериментальная предварительная версия для разработчиков от сообщества**:
>   не готова к промышленному использованию и еще не включена в upstream `libfprint`.
> - **Подтвержденное оборудование и прошивка**: USB `27c6:589a` под управлением OEM-прошивки
>   `GFUSB_GM168SEC_APP_10036` с OpenSSL 3 (`>= 3.0, < 4.0`).
> - **Безопасность аутентификации**: всегда сохраняйте резервный вход по паролю в
>   настройках PAM; показатели FAR/FRR на широкой выборке, режим сна/пробуждения
>   (suspend/resume) и альтернативные варианты прошивок остаются неподтвержденными.

## Сквозные принципы безопасности

1. **Никаких секретов и биометрических данных в git или issue**: никогда не публикуйте `psk.bin`, хеши PSK, DPAPI-объекты, таблицы калибровки, сырые дампы `.pgm`, сериализованные шаблоны `FpPrint`, дампы пакетов, образы прошивок или проприетарные бинарные файлы драйверов Windows.
2. **Подтверждение автономными синтетическими тестами против подтверждения на реальном оборудовании**: синтетические модульные тесты и KAT-тесты проверяют парсер, криптографию и логику ядра `libfprint` без оборудования; подтверждение на реальном оборудовании `27c6:589a` выполняется пользователем и ограничено узким кругом протестированных устройств.
3. **Восстановление в драйвере только для чтения**: при отсутствии `psk.bin` восстановление существующего PSK только в памяти без записи считывает исключительно ограниченные по размеру записи `0xE4`, работает строго в памяти и никогда не пишет в `/etc` и не отправляет деструктивные опкоды прошивки, стирания или инициализации (`0xA4`, `0xE0`, `0xF0`, `0xF4`).
